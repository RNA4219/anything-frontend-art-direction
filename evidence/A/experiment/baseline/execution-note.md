# 実行記録

## 作成した成果物

- `support-triage.plan.json`
- `course-catalog.plan.json`

両方とも `output-format.md` のオブジェクト形式で作成した。機能の維持・統合・延期・削除を決めた後に、画面責務、役割別の入口、ナビゲーション、目標への経路、primary / secondary 情報を指定した。入力にある役割・目標・要件・機能のIDと対応関係、既存のvisual_intentを保持した。

## 使用した入力ファイル

以下はすべて指定された `input` ディレクトリ内のファイルである。

| ファイル | 用途 |
| --- | --- |
| `support-triage.json` | 問い合わせ対応の役割、目標、必須要件、機能、実内容、境界条件、既存意匠の制約 |
| `course-catalog.json` | 講座の役割、目標、必須要件、機能、実内容、境界条件、既存意匠の制約 |
| `output-format.md` | JSONのフィールド、列挙値、mergeのtarget、primary / secondaryの意味 |
| `art-direction/SKILL.md` | 利用目的・利用者の判断・必要情報の関係を先に定め、今回必要な範囲の参照を選ぶ方針 |
| `art-direction/references/visual-composition.md` | 主判断に必要な情報と操作のまとまり、発見・比較・操作の責務、狭幅でも意味的な対応を保つ読み順 |
| `art-direction/references/c-usability.md` | 主にC-03、C-05、C-07、C-08、C-09、C-11、C2-08の業務語・一貫性・記憶負担・反復作業・必要情報・次の行き先の観点 |
| `art-direction/references/g-state-forms.md` | 「URLと履歴」の範囲。条件や対象を引き継いで戻る要求をBへ渡すために参照。API選定や状態遷移の実装には使用していない |

参照資料内の外部リンクは開いていない。外部検索、実物画面の観察、原典の仕様確認は行っていない。既存visual_intentを引き継ぐ情報設計のため、意匠の再設計や見本の探索は実施していない。

## 問い合わせ対応の決定

- `f_my_queue` を `f_inbox` の「自分の担当」ビューへ統合した。
- `f_assign`、`f_search`、`f_history`、`f_export` は維持した。担当変更と監査出力から履歴への依存も保持した。
- `f_trends` は初回必須ではないため延期し、対応する初回画面・ナビゲーションを作らなかった。
- `f_theme` は今回の目標・要件に対応しないため機能構成から削除する提案とした。
- 担当者の入口は問い合わせ一覧、管理責任者の入口は監査記録の出力とした。担当者向けに監査出力の入口は設けない。
- 検索0件でも現在の検索条件・90日の保持説明・条件見直し先が分かる構成とした。

### 問い合わせ対応の不確かな点

担当ルール本文、割当可能な担当、解決済みへの担当変更可否は入力にない。90日の保持の起算点、監査用記録の保持範囲、期間が参照する日時、出力対象の定義も未確定である。年4回の監査で必要な期間全体を取得できるかは、90日保持という情報だけでは保証できない。

初期一覧は未解決を対象とし、担当条件を全担当にする案を仮定として記録した。実運用の状態定義は要確認。10000件時のデータ取得・検索性能は未観測であり、権限と保持の実装契約も未確認として残した。

## 講座の決定

- `f_topics` と `f_workshops` を `f_catalog` へ統合した。トピックは複数所属できる属性とし、別の講座集合にはしない。
- `f_wishlist` を `f_favorites` へ統合し、「保存した講座」を同じ一覧のビューとした。
- `f_compare` と `f_details` は異なる判断を担うため維持した。比較時には2講座の同じ属性が対応して読める構成とした。
- `f_news` は今回の目標・要件に対応しないため機能構成から削除する提案とした。
- `f_publish` は編集者専用の管理・編集画面で維持し、受講者ナビゲーションから分離した。
- 参加前提、0円を含む価格、残席0を含む空席は、候補選択・比較・参加判断の画面でprimaryにした。
- 候補1件の比較画面には同じ講座一覧への追加先を設けた。申込先A/B/Cの対応は入力のまま維持し、実URLを補っていない。

### 講座の不確かな点

トピック内の複数選択をOR、別の条件軸同士をANDとすること、週末を土曜・日曜とすることを仮定として記録した。実際の日付・曜日・価格の検索用データ、各講座の安定したID、申込先の実URLは未提示である。

残席0で申込先に進んだ先の行動は未定義であり、キャンセル待ちなどの機能を追加していない。保存する利用者の識別と再訪時の復元範囲、公開状態の値、編集可能項目もproductへの確認事項とした。5000講座は将来の想定であり、性能問題の観測結果として扱っていない。

## 引継ぎと確認範囲

状態遷移、再試行、通知、戻り先での条件保持はBへ、具体的な部品・キーボード操作・読み上げ・ARIAはCへ引き継ぐ事項として各JSONに記載した。入力で定義されていない担当領域はproductに確認する。`blocking: true` は、その能力を実装・提供する前に解決が必要という意味である。

確認は作成した2ファイルをJSONとして読み込む構文確認のみ実施し、両方とも成功した。チェッカ、テスト、評価器、自己採点は実施していない。入力ディレクトリ外の資料、別の設計出力、親の会話は参照していない。書き込みは指定された `output` ディレクトリ内だけで行った。
