# Design QA task brief

画面をレビューし、利用目的を完了する際に問題となる箇所を日本語で報告する。
対象は以下の2つの架空画面。画面は変更しない。どちらも通信・実予約・個人データを使わない。

## 共有の視覚的意図

紙色の背景、黒鉛色の本文、赤茶の罫線、serifの大見出しと実務情報のsans serifを維持する。
見出しと本文の書体差、角の丸くない部品、非対称な上部構図は承認済みの表現である。
題材やコピーの好みは採点しない。文字が操作や理解を妨げる場合は具体的に示す。

## 登録画面 registration.html

目的：代表者が1〜8名の参加を1回登録し、受付番号を確認する。
名前は「確認 太郎」、メールは `qa@example.test`、人数は2名を標準データにする。
正常時は1回の申込につき受付済み件数が1増える。
入力の欠落・範囲外は送信前に修正できる。
通信失敗後は入力を維持し、同じ申込を再試行できる。
正常操作、通信失敗、人数の境界、素早い反復操作を対象にする。

## 一覧画面 requests.html

目的：依頼のページを移動し、処理待ちの依頼を見つける。
同じデータについて絞り込み件数と表示行が一致すること。
該当なしとページ範囲外を混同せず、条件を変更・解除して続けられること。
広幅と狭幅で見出し、状態、主要操作が互いを覆わないこと。
正常操作、該当なし、ページ移動後の絞り込み、320 CSS px相当の境界を対象にする。

## 実行条件

- HTMLは単体で開ける。初期状態はリロードで復元する。
- Desktop=1280×900、narrow=320×900、DPR=1、locale=ja-JPを基準とする。
- ブラウザを使えた範囲と、コードから予測した範囲を区別する。
- 対象HTML、brief、使うSkillとその参照以外の評価答案やoracleは読まない。
- 検証した手順・証拠、重要な問題、優先度、未確認事項を残す。

これは合成評価用fixtureであり、現行製品で発見された不具合ではない。
