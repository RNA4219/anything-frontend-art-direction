# 所見の適用例と不適用例

[入口](../SKILL.md) · [出力契約](../references/report-contract.md)

以下は**仮想の教材**であり、現行リポジトリに存在する欠陥や実測結果ではない。数値・selectorは例示で、実報告へそのままコピーしない。

## 適用例1 — 設定欄の長いラベルが操作を覆う

| 必須要素 | 仮想の記述例 |
| --- | --- |
| 位置 | `settings.html`、`#notification-frequency`、設定初期状態、viewport 320×720 CSS px。 |
| 症状 | 長い翻訳ラベルの末尾がselectの文字領域に重なり、現在の選択値を読めない。 |
| 根拠 | 要求REQ-NOTIFY-02は現在値を表示する。既存Art Directionはラベルと値の対応を維持する。Reflowについては対象と例外を原文で確認する。 |
| 影響 | 利用者は通知頻度を確かめずに設定を変更することになる。保存操作は可能なので、完了不能とは書かない。 |
| 修正方向 | 採用した書体・色を保ち、ラベルを折り返す領域と値の領域を分離する。Cへ実装確認を依頼する。 |
| 再現 | 320×720で初期化 → 長いロケールのラベルを表示 → selectを開かず値が読めるか確認 → 広幅と同内容で照合する。 |

主categoryはvisual。CSSの原因が確認できたらimplementationへの原因リンクを付ける。確認済みにするには該当状態のscreenshotと対象hashが必要。「余白を増やせばおしゃれ」という理由は不要。

## 適用例2 — 削除確認を取消した後、keyboardで作業を継続できない

| 必須要素 | 仮想の記述例 |
| --- | --- |
| 位置 | `playlist.html`、`#delete-confirm`をEscapeで閉じた直後、keyboard。 |
| 症状 | 確認を閉じても背景が操作不可のまま残り、Tabで次の項目へ移れない。 |
| 根拠 | 要求REQ-PLAYLIST-04の取消しは編集状態へ復帰する。ダイアログの期待する退出契約と照合する。 |
| 影響 | 削除を取りやめた利用者は再読込まで編集を継続できない。再読込で未保存変更が失われるかは別検証。 |
| 修正方向 | Bへ復帰状態の契約を確認し、Cへ背景操作制御とfocus復帰の解除を確認してもらう。 |
| 再現 | keyboardで削除を開く → Escape → Tab/Shift+Tab → 対象のfocusと操作可否を確認する。 |

主categoryはinteraction。screenshotだけではconfirmedにしない。browser_trace/test_logと実操作が必要。未保存変更の喪失を試していないなら断定しない。

## 不適用例 — 好みを不具合へ変換しない

| 元の批評 | そのまま採用できない理由 | 次の行動 |
| --- | --- | --- |
| 「AI Slopでダサい」 | 位置・症状・要求・影響を特定できない。 | どの状態のどの要素が何を妨げるか観察する。何も支持されなければpreference/noteで終える。 |
| 「余白が多すぎる」 | 編集的な意図か、比較を妨げる配置か不明。 | 比較対象が画面外へ分離し必要な判断を妨げるか確認。好みだけなら欠陥にしない。 |
| 「カードはすべて悪い」 | 特定表現を一律禁止する好み。 | 関連情報のまとまり、主操作、比較可能性を対象タスクで確認する。 |
| 「もっと短いコピーにすべき」 | 内容の好みだけではDの対象外。 | 実文量で欠け・重なり・ラベルの誤解がある場合に限って責務付きで記録する。 |
| 「この静止画は保存できないはず」 | 操作結果を画像から確定している。 | hypothesisとして保存操作を実行し、終端を確認する。 |
| 「自動検査0件なのでWCAG適合」 | 検査の対象ルール・状態が全過程と全要件を覆うとは限らない。 | rule subsetと未実施のmanual/AT試験を報告する。 |
| 「candidateの指摘が多いので優秀」 | 重複や誤検出を含むかもしれない。 | raw artifactで支持された所見と誤検出、未検出を分ける。 |
| 「別agentなのでprotected blind」 | context分離はOS上のアクセス隔離を保証しない。 | アクセス境界の証拠がなければpromotion HOLD。 |
| 「最小DOMテストが通ったのでブラウザ操作も成功」 | stubはCSS、native validation、focus等を実装していない場合がある。 | engineと検査範囲を明記し、ブラウザcaseは実行できるまでblocked/not_run。 |
| 「公開された旧画面を動かせたので、このfixtureも確認済み」 | URL/版/artifactが異なる。 | 公開版の証拠として保存し、candidateのhashへの対応を捏造しない。 |

## 修正済みと判定する例

同じ所見IDに対して新しいartifact hashを付け、元の再現手順を実行する。長いラベル・狭幅で現在値が読めることを新画像で確認した場合、visual所見をresolvedへ移せる。標準幅だけを見た場合は元の境界条件の解消を確認していないため、resolvedにしない。

修正後の状態に新たな所見があれば別IDを作る。旧所見を消して履歴を失わない。すべての未検証条件を「問題なし」へ置換しない。
